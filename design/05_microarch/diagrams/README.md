# ProtoEmu diagram conventions

- Use **solid arrows for data**: program words, payloads, pin values, capture results and numeric timestamps.
- Use **dashed arrows for control and status**: requests, handshakes, enables, and run or stop signals.
- When an interface carries both, draw separate, labeled arrows and show the direction of each. These are logical paths: separate arrows do not imply separate physical pins.
- Include the line-style key on each diagram. This project convention takes precedence over the draw.io hardware preset's default line styles.

Keep the editable `.drawio` and exported `.svg` together. Publish revisions as a new file pair and leave older pairs intact.

Colors follow the drawio-skill `hardware-architecture` preset: blue for logic clocked at 60 MHz, grey for combinational logic, white for external devices or neighbouring blocks.

The block diagrams (`blk-*_v1`) are generated by `scripts/block_diagrams.py` from one spec per block. To revise one, change its spec and write a new `_v2` pair; if you edit a `.drawio` by hand instead, stop regenerating that block. Validate with the skill's `validate.py` (warnings about the enclosure are expected), then export with draw.io: `draw.io -x -f svg --embed-svg-fonts false -o blk-X_v2.svg blk-X_v2.drawio`.

The [sequence diagrams](../sequences.md) share one editable Draw.io book. Regenerate with `python3 scripts/sequence_diagrams.py --layout-tool <drawio-skill>/scripts/seqlayout.py`; use `--out` for a new revision. Export each SVG with `draw.io -x -f svg --embed-svg-fonts false -b 16 -p N -o seq-NAME_v1.svg arch-b-sequences_v1.drawio`. For `N` from 1 through 8, the names are `chip`, `host`, `program`, `core`, `timer`, `drive`, `capture`, `pads`.
